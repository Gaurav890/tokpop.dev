# Collector 0.2.2 and contribution receipts v2

## Release order

1. Publish collector 0.2.2 to npm and verify its explicit-version command works outside this workspace. The updated website onboarding command requires this version.
2. Deploy the API and frontend together. The API uses the same database schema; it replaces legacy GitHub event rows only after a successful contribution lookup and any required private snapshot backup.
3. Existing users run the new collector's `watch --install` once to replace their bundled background collector. Updating npm alone does not replace an installed job. Do not re-pair a connected device.
4. Run `sync`, then `doctor`; after a scheduled run, confirm a recent successful automatic upload and no skipped sources. Sleeping/offline computers cannot provide continuous updates.
5. Open the share page to refresh GitHub receipts immediately. Successful collector uploads also trigger a receipt refresh when the last verified snapshot is at least six hours old. Confirm source timestamps and the dated GitHub window before sharing.

## Changes

- Scheduler presence and successful uploads are checked separately. Manual uploads cannot hide a broken automatic job. Failed and partial collection are reported.
- macOS app-bundled executable discovery and persisted executable/search paths fix sources missing only in background runs.
- Token headlines explicitly include reported cache usage. Component summaries reconcile to their selected daily totals; unknown portions remain unclassified.
- Contribution receipts use GitHub-defined 90-day account totals rather than the capped Events API. Private/restricted counts depend on visibility and permissions; missing coverage is not labelled as zero activity.
- Scoring methodology v2: delivery points are commit contributions + 3 × opened pull requests + 2 × reviews. Merged-PR and release points are removed because this query does not prove them. Restricted totals are never added. Snapshots older than 24 hours are labelled outdated and cannot produce a current ranked score until refreshed.
- Rank eligibility counts imported historical days; it does not impose a 30-day wait after signup. Fresh GitHub receipts are also required.

No production database, scheduler, npm release, or deployment is changed by applying the source patch alone.
